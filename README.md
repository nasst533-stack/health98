# 볼륨 기록 앱

운동 세트/횟수/무게, 유산소(트레드밀·계단 등), 식단 kcal·탄단지, 인바디(체중/골격근량/체지방률)를
2명이 함께 기록하는 개인용 웹앱입니다.
React + Firebase(Firestore)로 만들었고, **번들러(webpack/vite) 없이** 바로 동작합니다
(브라우저가 직접 지원하는 ES 모듈 + CDN을 사용).

## 1. Firebase 프로젝트 만들기 (5분)

1. https://console.firebase.google.com 접속 → 구글 계정으로 로그인 → "프로젝트 추가"
2. 프로젝트 이름 입력 (예: `my-workout-log`) → Google Analytics는 꺼도 됩니다 → 프로젝트 만들기
3. 왼쪽 메뉴 **데이터베이스 및 스토리지 > Firestore** → "데이터베이스 만들기" → 위치는 `asia-northeast3 (서울)` 추천 →
   처음엔 **테스트 모드**로 시작해도 되고, 프로덕션 모드로 시작했다면 아래 4번의 규칙을 붙여넣으세요.
4. Firestore **규칙(Rules)** 탭에 이 프로젝트의 `firestore.rules` 파일 내용을 그대로 붙여넣고 게시(Publish).
5. 왼쪽 메뉴 **빌드 > Authentication** → "시작하기" → 로그인 방법 탭에서 **이메일/비밀번호(Email/Password)** 를 사용 설정.
   (이 앱은 실제 이메일 대신 "이름"으로 로그인하지만, 내부적으로는 이메일/비밀번호 로그인 방식을 그대로 씁니다.)
6. 프로젝트 개요 옆 톱니바퀴 → **프로젝트 설정** → 아래로 스크롤 → "내 앱" → 웹 아이콘(`</>`) 클릭 →
   앱 닉네임 아무거나 입력 → "앱 등록" → **Firebase SDK 구성** 코드가 나오면 그 값들을 복사해두세요.
7. `src/firebase-config.js` 파일을 열어서 `firebaseConfig` 객체 안의 `YOUR_...` 부분을
   방금 복사한 값으로 바꿔서 저장합니다.

이제 이 앱은 실제로 동작하는 나만의 Firestore 데이터베이스에 연결됩니다.

### 첫 계정(마스터) 만들기 — 꼭 한 번 해야 해요

이 앱은 이름/전화번호/비밀번호로 가입하고, **마스터가 승인해야** 로그인해서 쓸 수 있어요.
그런데 맨 처음엔 승인해줄 마스터가 아직 없으니, 아래 순서로 첫 계정을 마스터로 직접 만들어주세요.

1. 앱을 열고 본인 이름/전화번호/비밀번호로 가입합니다. (가입 직후엔 "승인 대기 중" 화면이 나와요 — 정상입니다.)
2. Firebase 콘솔 왼쪽 메뉴 **데이터베이스 및 스토리지 > Firestore > 데이터** 탭으로 이동합니다.
3. `profiles` 컬렉션을 펼치면 방금 가입한 문서(임의의 uid 이름)가 보여요. 그 문서를 클릭합니다.
4. `approved` 필드 값을 `false` → `true`로 수정, `isMaster` 필드 값도 `false` → `true`로 수정합니다.
5. 앱으로 돌아와서 새로고침하면 정상적으로 로그인되고, 상단에 "승인" 탭도 보일 거예요.

이후 다른 사람(예: 같이 쓸 상대방)이 가입하면, 마스터 계정으로 로그인한 상태에서 상단 **"승인"** 탭에
이름/전화번호가 뜨고, "승인" 버튼만 누르면 됩니다. (비밀번호를 잊어버렸을 땐 이메일이 없어서
자동 찾기가 안 되니, Firebase 콘솔의 **Authentication > Users** 탭에서 마스터가 직접 새 비밀번호로 재설정해줘야 해요.)

## 2. 로컬에서 바로 테스트하기

가장 간단한 방법: `index.html` 파일을 그냥 더블클릭해서 브라우저로 엽니다.
(로그인 + Firestore 통신은 인터넷에 연결된 상태면 파일을 직접 열어도 정상 동작합니다.)

또는 간단한 로컬 서버로 열어도 됩니다:

```bash
npm run serve
# 브라우저에서 http://localhost:5173 접속
```

## 3. 실제 배포 (둘이 같이 쓰려면)

로컬 파일로도 되지만, 폰에서 URL로 바로 열고 싶다면 Firebase Hosting에 무료로 올릴 수 있습니다.

```bash
npm install -g firebase-tools   # 최초 1회
firebase login                  # 구글 계정 로그인
firebase use --add              # 방금 만든 프로젝트 선택
firebase deploy                 # 배포!
```

배포가 끝나면 `https://<프로젝트id>.web.app` 같은 주소가 나옵니다. 이 링크를 둘이 북마크해두고 쓰면 됩니다.

## 4. 코드를 수정했다면

`src/` 안의 `.jsx`/`.js` 파일을 수정한 뒤에는 아래 명령으로 다시 빌드해야
브라우저가 읽는 `dist/` 폴더에 반영됩니다.

```bash
npm install       # 최초 1회 (typescript 설치)
npm run build     # src/*.jsx -> dist/*.js 변환
```

## 5. 식단 kcal 데이터 채워넣기

`src/foods-data.js`에는 식약처 "식품영양성분DB정보" 공공API에서 받아온 자주 먹는
음식 20여 개 + 일반 참고값 몇 개가 들어있습니다. 각 항목의 `source` 필드가
`"api"`면 공공데이터포털 API 실측값, `"ref"`면 API에서 순수 원재료 형태를
찾지 못해 넣은 일반 참고값입니다.

**음식을 더 추가하려면 (API 방식, 추천):**

1. `scripts/import-foods-api.py`를 엽니다. (본인의 공공데이터포털 서비스키가
   이미 들어있습니다 — 이 프로젝트를 공개 저장소에 올릴 땐 이 파일은 빼거나
   키를 지우고 올리세요.)
2. 위쪽 `FOODS` 목록에 원하는 음식 검색어를 추가합니다.
3. 실행: `python3 scripts/import-foods-api.py`
   (이 API는 이 세션의 네트워크에서는 호출이 안 되니, 로컬 컴퓨터에서 실행해주세요)
4. 콘솔에 검색 후보들이 출력되니, 원하는 게 1번(0번 index)이 아니면
   `FOODS` 목록의 `pick` 값을 바꿔서 다시 실행하면 됩니다.
5. `src/foods-data.js`가 갱신됩니다.

이 API는 완제품/외식 메뉴 위주라 "순수 원재료" 검색이 잘 안 나올 때가 있어요
(예: 그냥 "바나나"보다 "바나나맛 도넛" 같은 게 먼저 나옴). 그럴 때는 그냥
저한테 음식 이름을 알려주시면 제가 찾아서 넣어드릴게요.

**엑셀 파일을 이미 갖고 계신 경우:** `scripts/import-foods.py`로 동일하게
가능합니다 (`INPUT_PATH`/`NAME_COL`/`KCAL_COL`을 실제 파일에 맞게 수정 후 실행).

## 6. 나중에 모바일 앱으로 만들기 ("어플화")

지금 이 앱은 그냥 웹페이지라서, 나중에 아래 방법으로 앱화할 수 있습니다.

- **가장 쉬운 방법 - PWA (홈 화면에 추가)**: 폰 브라우저에서 배포된 주소를 열고
  "홈 화면에 추가"만 하면 아이콘이 생기고 앱처럼 실행됩니다. 지금 구조 그대로 바로 가능합니다.
- **진짜 앱스토어/플레이스토어 배포**: [Capacitor](https://capacitorjs.com)로 이 웹앱을 그대로 감싸서
  iOS/Android 앱으로 빌드할 수 있습니다. Firebase 연결 코드는 그대로 재사용됩니다.

같은 Firebase 프로젝트를 계속 쓰면 되니, 지금 데이터가 나중에 앱으로 넘어갈 때도 그대로 유지됩니다.

## 문제 해결

- **콘솔에 "The query requires an index" 에러가 뜨는 경우**: 정상입니다. Firestore는 특정 조합의
  조회(예: 프로필별 + 날짜순 정렬)를 처음 실행하면 색인(index)을 만들라고 안내합니다.
  에러 메시지에 있는 링크를 클릭하면 자동으로 색인 생성 화면으로 이동하니, "만들기"만 눌러주면
  1~2분 뒤 정상 동작합니다.
- **화면이 하얗게만 나오는 경우**: 브라우저 개발자도구(F12) > Console 탭에서 에러 메시지를 확인해보세요.
  대부분 `src/firebase-config.js`의 값이 잘못 입력됐거나, Firestore/Authentication을
  아직 활성화하지 않은 경우입니다.

## 폴더 구조

```
index.html            앱 진입점 (이 파일을 열면 앱이 실행됨)
styles.css             전체 스타일
src/                    실제 소스 코드 (수정은 여기서)
  App.jsx               최상위 화면 구성
  firebase-config.js     ⚠️ Firebase 프로젝트 키 넣는 곳
  exercises-data.js      기본 운동 목록
  foods-data.js          기본 음식 kcal 목록
  store.js               Firestore 읽기/쓰기 함수 모음
  components/            화면별 컴포넌트
dist/                   src/를 빌드한 결과물 (브라우저가 실제로 읽는 파일, 직접 수정 X)
scripts/import-foods.py 식약처 엑셀 → foods-data.js 변환 스크립트
firestore.rules         Firestore 보안 규칙
firebase.json           Firebase Hosting 배포 설정
```

## 기능 요약

- 이름/전화번호/비밀번호로 가입 → 마스터 승인 후 로그인해서 사용 (마스터는 상단 "승인" 탭에서 가입자 이름·전화번호 확인 후 승인)
- 부위별(가슴/등/어깨/하체/승모/이두/삼두/전완/복근) + 유산소 운동 98종 기본 제공(바벨/덤벨/머신/케이블/맨몸 구분), 직접 추가도 가능
- 운동 검색 + 즐겨찾기(따로 모아보기)
- 웨이트: 세트/횟수/무게 입력 → 볼륨(무게×횟수 합) 자동 계산
- 유산소(트레드밀/계단 등): 시간/거리/경사/칼로리 입력
- 기록 탭: 운동별 히스토리 + 최근 추이 그래프, 달력에서 날짜별 볼륨(kg)·섭취 칼로리(kcal) 확인, 주간(7일) 볼륨/칼로리 그래프를
  이전 주로 넘겨볼 수 있음, 각 기록은 ⋮ 메뉴로 수정/삭제
- 인바디 탭: 체중/골격근량/체지방률 추이 그래프, 목표(다이어트/유지/벌크업) 설정 후 최근 7일 섭취·운동량과 비교한 요약과 조언,
  Gemini API 키를 입력하면 데이터를 종합한 AI 맞춤 팁도 받아볼 수 있음(키는 이 브라우저에만 저장됨)
- 식단: 음식 검색 → 섭취량(g 또는 개수 단위) 입력 → kcal·탄단지(g) 자동 계산, 오늘 총 섭취 요약, 목표별 탄단지 권장 비율과
  최근 7일 실제 비율 추이 그래프, 포화지방(참고용 추정치) 표시, 음식 직접 추가(개수 단위 등록 가능)
